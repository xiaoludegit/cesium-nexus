## M3 问题与修改建议

### P1 增量同步游标有漏数风险

位置：`packages/cli/src/commands/issue-cmd.ts`

现状：
- 同步成功后把 cursor 直接写成 `new Date().toISOString()`
- 这会让“同步过程中后来更新但未被本轮抓到”的 Issue 在下次 `since` 中被跳过

建议：
- cursor 改为本轮返回结果中的最大 `updatedAt`
- 若本轮无结果，保留旧 cursor
- 或者采用安全重叠窗口，避免边界漏数

### P1 多仓库游标未隔离

位置：`packages/storage/src/issue-repo.ts`

现状：
- `github_issues_last_sync` 是固定 key
- 不同仓库共用同一个同步游标

建议：
- 把 cursor key 改成按仓库区分，例如 `github_issues_last_sync:owner/repo`
- 或增加单独的同步状态表
- 补测试验证两个仓库不会互相污染游标

### P2 `--full` 清理语义不完整

位置：`packages/storage/src/issue-repo.ts`、`packages/storage/src/schema.ts`

现状：
- `clear()` 只删了 `issues`
- 计划里要求全量重建时同时清 `issues` 和 `issues_fts`

建议：
- `clear()` 显式清理主表和 FTS 表
- 或增加 rebuild 流程，确保索引一致
- 同时清理该仓库的同步游标

### P2 `--limit` 缺少输入校验

位置：`packages/cli/src/commands/issue-cmd.ts`

现状：
- `parseInt` 后没有校验
- `abc`、`0`、负数、`NaN` 都可能进入查询层

建议：
- 增加 `Number.isInteger(limit)` 和范围校验
- 非法值直接报错退出

### P2 文档状态需要同步

位置：`README.md`、`开发计划/plan.md`

现状：
- README 和计划里部分地方仍有 M3 之外的命令/阶段描述，容易让人误判当前完成度

建议：
- 把 M3 已完成内容、后续 M4/M5/M6 计划分清
- 避免把未实现能力写成当前可用
